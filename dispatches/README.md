# Research, Tool Notes & Field Notes

`DISPATCHES // NOTES FROM THE CONSOLE`

Some work is useful before it becomes a field manual. Dispatches hold focused research, tool assessments, laboratory observations and questions still being worked through.

## Choose the right kind of note

**Research** follows a question through sources and evidence. It should distinguish what the sources report from Darkcybe's analysis, and explain what would change the conclusion.

**Tool notes** answer a practical question: when is this tool useful, what does it produce, and where does it fall short? Versions and testing scope matter more than a feature list.

**Field notes** preserve a bounded observation or argument. They can be short and provisional. They still need honest attribution and enough context to avoid turning one observation into a universal rule.

Series names such as Tool Tuesday are editorial labels, not a publishing quota. A note should have something to say before it has a slot on the calendar.

When a dispatch develops into a repeatable method, its durable home is [Investigate](../investigate/README.md), [Detect](../detect/README.md), [Build](../build/README.md) or [Reference](../reference/README.md).
